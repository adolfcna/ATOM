# PE Structure & Dynamic Linking

The Portable Executable (PE) format is a file format for executables, object code, and DLLs used in 32-bit and 64-bit versions of the Windows operating system. This guide covers the creation and dynamic loading of DLLs.

---

## DLL Creation (`.dll`)

Below is an example of a Windows DLL written in C++. It uses `DllMain` to execute code upon load and `__declspec(dllexport)` to export a callable function without C++ name mangling.

<Tabs>
  <Tab title="Library Code (C++)">
    ```cpp
    #include <windows.h>
    #include <stdio.h>

    #pragma comment(lib,"user32.lib")

    // DLL entry point
    BOOL APIENTRY DllMain(HMODULE hModule,
                          DWORD  ul_reason_for_call,
                          LPVOID lpReserved)
    {
        switch (ul_reason_for_call){
            case DLL_PROCESS_ATTACH:
                MessageBoxA(NULL, "DLL Loaded!", "Info", MB_OK);
                break;
            case DLL_PROCESS_DETACH:
            case DLL_THREAD_ATTACH:
            case DLL_THREAD_DETACH:
                break;
        }
        return TRUE;
    }

    // --------- Exported Function ---------
    extern "C" {

    __declspec(dllexport) BOOL WINAPI RunMe(void){
        MessageBoxA(NULL, "Exported function called!",
                    "Hello from DLL", MB_OK);
        return TRUE;
    }
    }
    ```
  </Tab>
  <Tab title="MSVC Build (cl.exe)">
    To build the DLL on Windows using the Microsoft Compiler:
    ```powershell
    cl.exe /D_USRDLL /D_WINDLL implant.cpp /MT /link /DLL /OUT:implant.dll
    ```
    * `/D_USRDLL` and `/D_WINDLL` marks the build as a DLL.
    * `/MT` statically links the runtime.
    * `/link /DLL /OUT:implant.dll` produces the output DLL file.
  </Tab>
  <Tab title="MinGW Build (g++)">
    To build a DLL with MinGW on Windows (64-bit & 32-bit):
    ```bash
    # 64-bit
    x86_64-w64-mingw32-g++ -D_USRDLL -D_WINDLL -shared -static -o implant.dll main.cpp -lws2_32 -lwininet -ladvapi32 -Wl,--out-implib,libimplant.a

    # 32-bit
    i686-w64-mingw32-g++ -D_USRDLL -D_WINDLL -shared -static -o implant.dll main.cpp -lws2_32 -lwininet -ladvapi32 -Wl,--out-implib,libimplant.a
    ```
    * `-shared -static` builds a shared static DLL.
    * `-lws2_32 -lwininet -ladvapi32` links required Windows libraries.
    * `-Wl,--out-implib,libimplant.a` generates an import library for linking.
  </Tab>
</Tabs>

<Callout type="info" title="Key Concepts">
* `DllMain` is called automatically when the DLL is loaded/unloaded or a thread is created/terminated.
* `__declspec(dllexport)` marks `RunMe` as an exported function callable from other programs.
* `extern "C"` prevents C++ name mangling, allowing the function to be called by its plain name.
</Callout>

## Dynamic Loading (`LoadLibrary`)

To load a DLL at runtime, you use the `LoadLibraryA` API. The following C code demonstrates how to load the library and call its exported function.

```c
#include <windows.h>
#include <stdio.h>

typedef BOOL (WINAPI *RunMe_t)(void);

int main()
{
    // Load the DLL
    HMODULE hDll = LoadLibraryA("YourDll.dll");
    if (!hDll) {
        printf("Failed to load DLL\n");
        return 1;
    }
    
    // Get the address of the exported function
    RunMe_t RunMe = (RunMe_t)GetProcAddress(hDll, "RunMe");
    if (!RunMe) {
        printf("Failed to find RunMe\n");
        return 1;
    }
    
    // Call the function
    RunMe();
    
    // Free the DLL
    FreeLibrary(hDll);
    return 0;
}
```

<Callout type="tip" title="Windows API Functions">
* `LoadLibraryA("YourDll.dll")` loads the DLL into the process address space.
* `GetProcAddress(hDll, "RunMe")` retrieves the address of the exported function.
* `FreeLibrary(hDll)` decrements the reference count and unloads the DLL when no longer needed.
</Callout>

## Execution via `rundll32.exe`

You can invoke an exported DLL function directly from the Windows command line without writing a custom loader.

```cmd
rundll32.exe mydll.dll,RunMe
```

<Callout type="warning" title="Quick Execution">
This is a quick way to test DLL exports, but note that `rundll32.exe` is heavily monitored by EDRs and security solutions.
</Callout>
